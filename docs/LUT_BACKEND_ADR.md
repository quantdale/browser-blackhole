# ADR M8-01 — Optimized Schwarzschild LUT backend design

Status: ACCEPTED for implementation (M8)
Date: 2026-08-22
Owner: black-hole phenomenon module (`src/phenomena/black-hole/lut/`)

## 1. Primary reference and provenance

- Paper: Eric Bruneton, "Real-time High-Quality Rendering of Non-Rotating
  Black Holes", arXiv:2010.08735 (2020). Method summary: beam tracing with
  PRECOMPUTED TABLES so each pixel's ray deflection and accretion-disc
  intersections are found in constant time, plus a custom texture-filtering
  scheme for star fields under strong magnification.
- Reference implementation: `github.com/ebruneton/black_hole_shader`,
  BSD-3-Clause. C++ precompute + GLSL runtime. Key constants observed in its
  documentation: `RAY_DEFLECTION_TEXTURE` 512x512, `RAY_INVERSE_RADIUS_TEXTURE`
  64x32, nonlinear axis remap `u(e^2) = 1/(1+6*e^2)`.
- Provenance classification: CONCEPTS ADAPTED, CODE INDEPENDENT. No GLSL/C++
  from the reference implementation is copied. All tables are generated by
  this repository's own generator from this repository's own binary64 CPU
  reference solver (`src/phenomena/black-hole/cpuReference.ts`), which remains
  the numerical oracle. See `docs/ASSET_PROVENANCE.md` §"Bruneton references".

## 2. Coordinate conventions (ours)

Identical to `docs/NUMERICAL_METHODS.md`; restated because the table axes
must be understood physically:

- Geometric units `G = c = 1`, lengths in `r_g = GM/c^2`, mass parameter
  `M = 1`. Horizon `r = 2`, photon sphere `r = 3`, ISCO `r = 6`, critical
  impact parameter `b_c = 3*sqrt(3) ~= 5.196152`.
- Every camera ray reduces to a geodesic PLANE spanned by the radial unit
  vector `e0` (observer -> away from center) and the in-plane tangent `e1`
  (component of the local ray direction orthogonal to `e0`). The planar state
  is `(r, phi, p_r)` with conserved `L` (E-normalized, so `b = L/E` is stored
  directly). World embedding: `pos = C + r*(cos(phi) e0 + sin(phi) e1)`.
- Backwards ray tracing from a static observer; terminal escape direction is
  the tetrad projection of `(v_r, v_t) = (f p_r, L/r)` back to world axes,
  exactly like the numerical backend's `escapeDirectionFn`.

## 3. Ray/beam parameterization — why ONE table family suffices

A Schwarzschild null geodesic is fully characterized by its conserved impact
parameter `b` (plus which branch of the curve the photon occupies). The
trajectory curve `T_b` — incoming from infinity, periapsis at `r_min(b)`
(for `b > b_c`), outgoing to infinity; or winding into the horizon (for
`b < b_c`) — is a property of `b` ALONE. An observer at any radius `r0`
simply intercepts the same curve at the azimuth where it crosses radius
`r0`. Therefore:

- The trajectory tables are indexed by `b` only; there is NO observer-radius
  table dimension. Observer position enters only through (a) the analytic
  initial-state math shared with the numerical path, and (b) locating the
  launch azimuth on the tabulated curve (section 5).
- Per-pixel `b` is computed analytically (closed-form tetrad mapping, already
  implemented in both CPU reference and GPU integrator):
  `b = r0 * |n_tangential| / sqrt(f(r0))`.

This mirrors the paper's insight that precomputation collapses the per-pixel
ODE integration into table lookups; our normalization uses `b` itself rather
than his inverse-radius/eigenvalue form `(u, e^2)` with `e^2 ~ (b_c/b)^2`;
the correspondence is monotone and recorded here for traceability.

## 4. Precomputed quantities

Family `schwarzschild-v1` (all generated offline from the CPU reference):

1. **Trajectory table** `traj`: `r(psi; x)` where `psi >= 0` is accumulated
   in-plane azimuth measured from the INCOMING crossing of the reference
   sphere `r_ref` (chosen at/above the production escape radius), and
   `x = b / b_c` is the normalized impact parameter. One row per `x` sample;
   the row spans incoming branch -> periapsis (or horizon capture) ->
   outgoing branch back to `r_ref`. Stored as a filterable 2D texture.
2. **Per-row auxiliaries** `aux` (1D texture, one texel per `x`): packed
   status flags (escaped / captured / winding-truncated), `r_min`,
   `psi_periapsis`, `psi_exit` (azimuth of the final `r_ref` crossing on the
   outgoing branch; undefined/marker when captured), and the terminal
   tetrad-projected escape-direction components `(n_r, n_t)` evaluated at
   `r_ref` on the outgoing branch (undefined when captured).
3. **Derived scalars** in the manifest: effective critical boundary used by
   the generator, table domains, error summary vs the numerical oracle.

Runtime quantities NOT tabulated (analytic, cheap, shared with the numerical
backend): per-pixel `b`; geodesic-plane basis `e0/e1`; plane normal
`N = normalize(cross(e0, e1))`; axial impact parameter `b_z = b * dot(N, +Y)`
used by the disk redshift; world re-embedding trigonometry; disk emission;
environment sampling; g-factor arithmetic.

## 5. Observer-radius dependence and launch azimuth

The launch azimuth `psi_launch(x; r0)` solves `r(psi; x) = r0` on the
incoming branch. Because rows are monotone decreasing in `psi` from `r_ref`
to `r_min`, a bounded Newton iteration (fixed iteration count, hardware-
filtered reads) converges in ~4-6 lookups. Rays launched OUTWARD (`n_r > 0`)
with `b < b_c` still terminate captured: they climb to the turning radius
`r_turn(b) < 3` and fall back onto the SAME tabulated curve; the runtime
selects the correct branch from the sign of the radial momentum using the
row's apsis symmetry, mirroring the reference implementation's
`u_dot > 0` mirror logic. Outward rays with `b > b_c` escape without ever
entering the strong field: their deflection is looked up symmetrically and
their environment sample equals the numerical result within tolerance.

## 6. Critical-region behavior

Near `x = 1` the total winding diverges logarithmically and `r(psi; x)`
varies steeply across rows. Mitigations, selected by measurement (M8-04,
tools/generate-luts/study.ts, 12 off-grid oracle-compared columns per
config):

- NONLINEAR `x` AXIS — MEASURED WINNER: piecewise-linear knots
  `xKnots = [0, 0.70, 1.30, 3]` (one third of columns inside
  [0.70, 1.30]). It beat both a default [.85, 1.15] split and a tight
  [.95, 1.05] band on BOTH radius-error statistics at w=1024
  (max 3.05e-2 r_g, rms 1.18e-2 vs 5.20e-2/2.21e-2 and 7.63e-2/2.58e-2);
  over-concentrating columns near criticality starves [0.85, 0.95)
  where strong-lensing disk hits live.
- ROW RESOLUTION: psi is NOT the bottleneck — h=2048 measured within
  noise of h=1024 while h=512 regressed; h=1024 frozen.
- FINITE WINDING BUDGET: psiMax=16 rad; MEASURED winding grows only like
  ~(1/2)ln(1/(x-1)) (x=1.001 -> 4.65 rad), so no numerically reachable
  column truncates; hybridBandHalfWidthX=0 for the shipped family and
  the runtime still honors it as an explicit fallback trigger.
- STEEP OUTER RIM (documented limitation): beyond ~16 r_g the row tail
  turns nearly radial (dr/dpsi > 100 r_g/rad); disk-hit error sampling
  excludes it via slope guard, and M8-07 image equivalence owns the
  rim's visual verdict.
- Classification near the boundary is EXACT by construction: escaping
  class <=> b > b_c analytically; measured mismatch rate 0 across every
  generated family (manifest validation block).

## 7. Disk intersection implications

The thin disk is the world equatorial plane (+Y normal, WORLD_FRAME §1).
Along the tabulated curve, the world height is

    z(psi) = r(psi; x) * u_y(psi),   u_y(psi) = cos(psi')*e0.y + sin(psi')*e1.y

where `psi' = psi - psi_launch` is azimuth relative to the observer radial
direction and `u_y` is a pure sinusoid in `psi'`. Its zeros are therefore
EQUALLY SPACED in `psi` with phase/amplitude fixed analytically by the plane
orientation — NO root-finding in `r` is needed. Each candidate crossing
azimuth yields `r_hit` via one filtered texture read; acceptance is the same
annulus test `[inner, outer]` as the numerical path; higher-order images
emerge from successive half-turn spacings within the winding budget, exactly
as they emerge from continued RK4 integration today. Emission/redshift reuse
`makeDiskEmissionNode` verbatim with analytic `g(b_z, r_hit)` — the SAME
code path as the numerical backend (no second emission model).

Bounded image orders: crossings beyond the row's `psi_max` do not exist in
the table; the truncation band is inside the already-hybrid-routed region
(section 6), so no visible disk image is silently dropped.

## 8. Background/star filtering implications

The paper adds a beam-footprint filtering scheme so tiny bright stars are
integrated over the magnification-changed beam cone instead of point-sampled
at the center ray. Our environment is a PROCEDURAL cell-based starfield
(`src/shaders/starfieldGpu.ts`), not a Gaia point catalog; star angular
footprints are already finite (quadratic falloff over a cell-scale radius),
which changes how magnification aliasing manifests (brightening/thinning near
the critical curve rather than popping point stars).

Decision for M8: center-ray direction lookup (identical to the numerical
backend's behavior), PLUS a dedicated aliasing investigation on the mission
scenarios (ordinary field, near critical curve, high magnification, camera
motion). If measurable aliasing beyond the numerical backend's own behavior
is found, either adopt a footprint-widened falloff or DOCUMENT the limitation
in this ADR and STATE.md. Full beam tracing is explicitly out of scope for
the first LUT backend.

## 9. Precision assumptions

- Generator: binary64 CPU reference, converged settings (tighter than
  production numerical defaults), convergence evidence recorded per fixture.
- Runtime textures: format chosen by measured interpolation error
  (candidates RG16F/RG32F/RGBA16F/RGBA32F); WebGL2 filterability is a hard
  constraint — if the winning format is not filterable in WebGL2, either use
  the compatible format or truthfully fall back to numerical under WebGL2.
- f32 runtime arithmetic matches the existing integrator's guard policy
  (SHADER_CONTRACTS §14); table outputs feed the same sanitization.
- Equivalence tolerances are quantity-specific (classification exact outside
  the documented hybrid band; escape-direction angular tolerance; disk-hit
  radius tolerance; g-factor relative tolerance), recorded in
  `docs/VALIDATION_VECTORS.md` additions and enforced by tests.

## 10. Explicitly out of scope (honest limits)
- Beam-traced star filtering (paper section on beams) — investigated,
  documented, possibly deferred (section 8).
- Time-of-flight / retarded time (the reference stores propagation time per
  sample; our renderer has no time-delayed shading consumer yet).
- Kerr/spinning extension (M9 will need its own family; schema reserves the
  `physicsConvention` field).

## 11. Auto-default decision criterion (M8-08) — FIXED BEFORE MEASUREMENT

To prevent post-hoc threshold tuning, the definition of a "meaningful
performance win" was written down BEFORE the paired numerical-vs-LUT
measurement campaign ran. The harness is `scripts/bench-black-hole.mjs`
(matched conditions: same preset, quality tier, viewport, pinned render scale,
warm-up, sample count; backend set through canonical state, M8-09).

**LUT becomes the `auto` default (`LUT_AUTO_DEFAULT = true`) only if ALL of:**

1. **Headline win:** median frame-time improvement ≥ 10 % on the
   representative `default` preset at the primary mainstream internal
   resolution (1280×720-class CSS viewport, render scale 1);
2. **No scene regression:** no measured scene shows a median regression
   greater than 5 %;
3. **Tail safety:** p95 frame time regresses by at most 10 % on every scene;
4. **Reproducibility:** the sign of the median delta is stable across ≥ 2
   repeated runs per scene (noise guard; more repeats if noisy);
5. **Fidelity unchanged:** all equivalence gates stay green
   (`lutEquivalence` corpus, integrator parity on both backends, goldens).

Otherwise numerical REMAINS the auto default and M8-08 records the honest
(marginal/negative/hardware-specific) outcome. A technically correct negative
result is acceptable and explicitly preferred over adoption justified by
sunk cost. Manual selection (`numerical`/`lut`) and truthful fallback are
preserved in either branch.

Measured scenes: `default` (typical), `face-on-disk` (easy/escape-heavy),
`edge-on-lensing` (disk-heavy), `photon-ring` (critical-region). Results are
recorded under `benchmarks/` and summarized in `.agent/STATE.md`.

Criterion verdict (§11): (1) headline ≥10 % — PASS; (2) no scene median

### M8 validation-debt closure — GPU-path defects found and FIXED

Extending the browser parity corpus to the LUT execution path exposed three
real defects in `lut/lensingGpu.ts` that the CPU-level M8-07 corpus could not
see (its terminal-direction tolerance had been DEFERRED, not asserted). All
three are fixed at the root cause; the browser corpora now enforce:

1. **FRAME-ORIGIN FIX** — table rows/aux live in launch coordinates (φ=0 at
   the r_ref=64 inbound crossing); the pass embeds φ=0 at the OBSERVER. The
   code had used `psiApsis` directly, rotating every LUT-resolved ray by the
   camera-dependent angle `psiApsis − launchRow`. Correct mapping: folded row
   `|φ_obs − launchRow|`, exit azimuth `launchRow + arcEnd`.
2. **CROSSING SELECTION** — the ascending-arc selection loop re-selected the
   same crossing on every pass (window test `>=` with a per-pass reset best),
   multiplying disk emission up to 4×. Exclusion is now by candidate azimuth.
3. **PHI-STAR RATIO** — the plane-height zero used `atan(e1.y/−e0.y)` (the
   PERPENDICULAR angle) instead of `atan(−e0.y/e1.y)`, transplanting the
   entire disk image by ≈90° per pixel plane.

Post-fix evidence: numerical-vs-LUT whole-frame mean delta 0.09/255
(doppler-demo view, forced linear chain); terminal-direction agreement
≤ ~1° across the sky on both renderer APIs; integrator parity corpus green
on all four (api × trajectory) rows; cross-backend disk luminance agreement
at matched probes ≤ 8/255.
